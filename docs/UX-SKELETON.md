## 0. עקרון העל — שני מצבי נוכחות

יום של צלם מקצועי אינו "גלישה במערכת". הוא מתחלק לשניים, והם דורשים ממשקים הפוכים:

| | **מצב מכ"ם** | **מצב עבודה עמוקה** |
|---|---|---|
| מתי | בין סשנים, בבוקר, אחרי טלפון מלקוח | שעה עד חמש שעות ברצף |
| שאלה מנחה | "מה דורש ממני משהו?" | "תן לי לעבוד ואל תפריע" |
| היכן | היום · פרויקטים · יומן · לקוח | בתוך פרויקט: סינון · עריכה · אלבום |
| צפיפות | מעט פריטים, כל אחד בר-פעולה | כל הרוחב לתמונה, כרום מינימלי |
| משך | דקות | שעות |

**שלושה כללים שנגזרים מזה, וכל השלד מציית להם:**

1. **הסיידבר משרת, לא שולט.** במצב עבודה עמוקה הוא מתכווץ ומפנה מקום לתמונה.
2. **אין מסך שהוא דוח בלבד.** כל פריט שמוצג הוא **דלת** — לחיצה עליו מגיעה למקום שבו מטפלים בו. מספר שאי אפשר ללחוץ עליו לא מוצג.
3. **עבודה לא הולכת לאיבוד.** יציאה מפרויקט לענות ללקוח ובחזרה — חוזרים **בדיוק** לאותה תמונה, אותו זום, אותו מתכון.

**מה נדחה במכוון ⛔:** דשבורד של כרטיסי סטטיסטיקה · מודולים שווי-מעמד בסיידבר · אשף רב-שלבי ליצירת פרויקט · הכל בכרטיסים. אלה תבניות SaaS גנריות, והן לא מתארות את היום של צלם.

## 1. מפת ניווט מלאה

### 1.1 הציר העסקי — סיידבר קבוע (6 פריטים)

```
היום          ← מסך הנחיתה. תור עבודה, לא דוח.
פרויקטים      ← כל העבודות. רשימה, מסננת, מצב.
לקוחות        ← אנשים. היסטוריה, כסף, תקשורת.
יומן          ← צילומים קרובים ודדליינים.
─────────
הגדרות        ← חשבון, מנוי, מיקומי אחסון, תבניות, מיתוג.
```

📋 **"משימות" אינו פריט סיידבר.** משימה תמיד שייכת למשהו — לפרויקט או ללקוח. היא חיה בתוך "היום" (התור) ובתוך הפרויקט. יש תצוגת "כל המשימות" מתוך "היום", לא ערוץ ניווט משלה. סיידבר של שישה פריטים נשאר קריא; של תשעה כבר לא.

📋 **"היום" ולא "דשבורד".** השם מגדיר את התפקיד. "דשבורד" מזמין כרטיסי מדדים; "היום" מזמין תור פעולות.

### 1.2 הציר של הפרויקט — פס שלבים בתוך הפרויקט

```
הכנה → ייבוא → בחירה → עריכה → אלבום → מסירה
```

זהו ציר **מקומי לפרויקט**. הוא אינו מופיע בסיידבר ואינו קיים מחוץ לפרויקט.
🔒 בכך מתבטלת הכפילות הקיימת היום (סיידבר וטאבים שמובילים לאותם מסכים).

### 1.3 שכבות-על גלובליות (זמינות מכל מקום, אינן "מסכים")

| שכבה | תפקיד | הפעלה |
|---|---|---|
| **חיפוש** | "כהן" → קפיצה ללקוח/פרויקט/תמונה | Ctrl+K וגם שדה קבוע |
| **משימות רקע** | ייבוא · רינדור · העלאה — עם התקדמות וביטול | מגירה מהפס העליון |
| **מצב מערכת** | מנוע · דיסק · חיבור · מנוי | מופיע **רק כשיש בעיה** |
| **חשבון** | משתמש, מנוי, חבילה | פינה |
| **חזרה לעבודה** | שבב שמחזיר לנקודה המדויקת שממנה יצאת | מופיע כשיש עבודה פתוחה |

📋 **חיפוש הוא תשתית, לא נוחות.** צלם עם 200 לקוחות מהעבר לא ינווט אליהם בעץ.

### 1.4 מה יוצא מהניווט הקיים 🔒

| היום | לאן עובר |
|---|---|
| גלריות · סינון גלריה · עיבוד גלריה · עיצוב אלבומים | לשלבים בתוך פרויקט |
| מעבדה · קריאת עריכה | למצב "בדיקה" בתוך שלב העריכה |
| הזמנות ומוצרים | ⛔ מחוץ ל-v1 |
| דוחות | תמונת מצב בתוך "היום" ובדף הלקוח; אין מסך דוחות |
| סטטוס לקוח (טאב) | מתמזג לתוך מעטפת הפרויקט — הוא הקשר, לא שלב |

### 1.5 המפה בשלמותה

```
היום
פרויקטים ──→ פרויקט ──→ [הכנה · ייבוא · בחירה · עריכה · אלבום · מסירה]
                 └──→ פאנל הקשר: לקוח · תשלומים · משימות · תקשורת · קבצים
לקוחות ────→ לקוח ────→ רשימת הפרויקטים שלו ──→ (חזרה לפרויקט)
יומן ──────→ יום/שבוע ─→ (חזרה לפרויקט)
הגדרות
```

**שים לב שכל חץ הוא דו-כיווני.** מלקוח מגיעים לפרויקט, ומפרויקט ללקוח, בלי לאבד מקום.

## 2. מסך "היום" — מבנה

### 2.1 שלושה אזורים, לא כרטיסים

```
┌─ פס עליון: מה קורה היום ────────────────────────────────┐
│  צילום היום · או · "אין צילומים היום"                    │
└─────────────────────────────────────────────────────────┘
┌─ תור העבודה (עיקר המסך) ───────────┐ ┌─ הקרוב ביותר ──┐
│  פריט · פריט · פריט…                │ │  יומן 14 יום   │
│  מסודר לפי דחיפות אמיתית            │ │  צילומים       │
│  כל פריט = דלת לנקודה המדויקת       │ │  דדליינים      │
└────────────────────────────────────┘ └────────────────┘
┌─ שורת מצב עסקית (שורה אחת, לא כרטיסים) ─────────────────┐
│  N פרויקטים פעילים · N ממתינים ללקוח · ₪N לגבייה         │
└─────────────────────────────────────────────────────────┘
```

### 2.2 סוגי הפריטים בתור

| פריט | הפעולה שהוא פותח |
|---|---|
| הלקוח סיים לבחור | פתיחת שלב העריכה עם הסט שנבחר |
| גלריה מוכנה ולא נשלחה | מסך המסירה של אותו פרויקט |
| אלבום ממתין לאישור מעל X ימים | שליחת תזכורת ללקוח |
| התקבלו הערות על אלבום | הכפולה הראשונה שיש עליה הערה |
| רינדור הסתיים | תיקיית הפלט / מסך המסירה |
| תשלום פתוח אחרי מסירה | דף הלקוח, מוקד תשלומים |
| צילום מחר | הפרויקט, שלב הכנה |
| משימה ידנית | היעד שהוגדר לה |

📋 **סדר לפי דחיפות אמיתית, לא לפי תאריך יצירה:** לקוח ממתין > כסף פתוח > דדליין קרוב > הכול השאר. לקוח שממתין הוא הפריט היקר ביותר בעסק.

### 2.3 מצב ריק (משתמש חדש)
פעולה **אחת** במרכז המסך: "צור פרויקט ראשון". בלי גרפים ריקים ובלי אפס-אחוזים.

## 3. המבנה הפנימי של פרויקט

### 3.1 מעטפת קבועה — נשארת בכל השלבים

```
┌─ פס מצב הפרויקט (תמיד גלוי, שורה אחת) ──────────────────┐
│ משפחת כהן · בת מצווה · 12.05 │ שלב: עריכה │ 1,842→214→96 │
│ ממתין: —   │ קבצים: זמינים   │ רקע: רינדור 96/214 ⏸      │
└─────────────────────────────────────────────────────────┘
┌─ פס השלבים ─────────────────────────────────────────────┐
│ הכנה ✓  ייבוא ✓  בחירה ✓  ●עריכה  אלבום  מסירה           │
└─────────────────────────────────────────────────────────┘
┌─ מרחב עבודה של השלב ───────────────────┐ ┌─ הקשר ⇄ ──┐
│                                        │ │  מתקפל     │
└────────────────────────────────────────┘ └───────────┘
```

### 3.2 פס השלבים — שלושה כללים

1. 🔒 **מציג מצב, לא רק שם:** לא התחיל · בעבודה · ממתין ללקוח · הושלם. "ממתין ללקוח" הוא מצב בפני עצמו — הצלם לא תקוע, הוא מחכה.
2. 📋 **מותאם לתוצרים של הפרויקט:** פרויקט בלי אלבום **לא מציג שלב אלבום**. התוצרים נקבעים בשלב ההכנה. משפחתי מהיר לא ייראה כמו חתונה.
3. 🔒 **אינו שער.** אפשר לחזור לעריכה אחרי שהאלבום התחיל, ואפשר לדלג. השלבים מתארים היכן הדברים עומדים, לא מה מותר.

### 3.3 פאנל ההקשר (צד, מתקפל)

לקוח ויצירת קשר · תשלומים (סוכם / שולם / פתוח) · משימות של הפרויקט · היסטוריית תקשורת · מיקום הקבצים בדיסק · הערות.

📋 מתקפל אוטומטית בסינון ובעריכה, ונפתח בהכנה ובמסירה. במצב עבודה עמוקה הוא גוזל רוחב מהתמונה.

### 3.4 מרחב העבודה לפי שלב

| שלב | צורת המרחב |
|---|---|
| הכנה | טופס קצר + הגדרת תוצרים |
| ייבוא | מקור הקבצים + התקדמות + מה נמצא |
| בחירה | **מסך מלא**, מקלדת, כרום מינימלי |
| עריכה | תמונה גדולה + פאנל מתכון + סרט תמונות + מצב "בדיקה" |
| אלבום | כפולות + מגש תמונות + פריסות (המודול הקיים) |
| מסירה | מה יוצא · לאן · מה נשאר · מצב |

## 4. לקוח מול פרויקט 🔒

### 4.1 המודל

```
לקוח (1) ──< פרויקט (N) ──< תמונות · גלריות · אלבומים · מסירות
```

* **לקוח** = מי שמשלם ומי שחוזר. פרטי קשר, כל הפרויקטים לאורך השנים, סך תשלומים, כל התקשורת, העדפות ("אוהב חם", "משלם באיחור").
* **פרויקט** = עבודה אחת. אירוע אחד, תאריך אחד, מסירה אחת (או יותר).

### 4.2 יצירה — חייבת להיות מהירה

📋 **פרויקט נוצר בשדה אחד: שם.** בחירת לקוח קיימת **או הקלדת שם חדש שיוצרת לקוח במקום**. צלם שסוגר חתונה בטלפון לא ילך ליצור לקוח ואז לחזור. כל השאר (תאריך, סוג, תוצרים, מחיר) נשלם בשלב ההכנה או אחר כך.

### 4.3 דף הלקוח

ציר זמן של הפרויקטים שלו · מצב תשלומים מצטבר · כל התקשורת במקום אחד · הערות · פעולה ראשית: **"פרויקט חדש ללקוח הזה"**.

### 4.4 מחיקה וארכוב
📋 פרויקט מסתיים → **ארכוב**, לא מחיקה: יוצא מהתור ומהרשימה הפעילה, נשאר בהיסטוריה של הלקוח. מחיקת לקוח אינה מוחקת את ההיסטוריה הכספית.

## 5. סדר הזרימה — שישה שלבים

> **תובנה שקובעת את המבנה: "מסירה" אינה אירוע אחד בסוף.** גלריה לבחירה נשלחת באמצע, הגהת אלבום נשלחת אחריה, והקבצים הסופיים בסוף. לכן מסירה היא **גם שלב וגם פעולה** שזמינה משלבי הבחירה והאלבום. אחרת הזרימה שבורה: אי אפשר "לבחור" לפני ששולחים.

### שלב 1 — הכנה
* **מטרה:** להגדיר מה העבודה ומה יוצא ממנה.
* **קלט:** לקוח, סוג אירוע, תאריך, מיקום, סכום מוסכם.
* **החלטה מרכזית:** **התוצרים** — גלריה לבחירה? כמה תמונות כלולות? אלבום? קבצים סופיים? זה מה שמעצב את פס השלבים.
* **סיום:** יש לקוח, תאריך ותוצר אחד לפחות.
* **מלכודת:** טופס ארוך. שלושה שדות חובה, השאר בהמשך.

### שלב 2 — ייבוא
* **קלט:** תיקייה על הדיסק.
* **המערכת:** סורקת, מייצרת תמונות ממוזערות, סופרת, מזהה כפולים ופורמטים.
* **משימת רקע** עם התקדמות, ניתנת לעצירה והמשך; האפליקציה נשארת שמישה.
* **סיום:** כל הקבצים נסרקו ויש להם ממוזערות.
* **מצב כשל שחייב תצוגה מכובדת:** כונן חיצוני מנותק → "הקבצים אינם נגישים כרגע", עם המיקום המדויק ואפשרות לאתר מחדש. לא הודעת שגיאה אדומה.
* ❓ **פתוח:** הפניה למקום המקורי או העתקה לתיקיית פרויקט.

### שלב 3 — בחירה
שני תת-שלבים שאסור לבלבל ביניהם:

**3א — סינון של הצלם.** מסך מלא, מקלדת, מהיר: שמור/פסול/דגל, מעבר אוטומטי. 1,842 → 400. זהו המקום שבו נשרפות שעות, ולכן הוא המסך הכי נקי במערכת.

**3ב — בחירת הלקוח** (אם הוגדרה בתוצרים). מפעילה **מסירה** של גלריה. הפרויקט עובר למצב **"ממתין ללקוח"** עם תאריך שליחה ותאריך צפייה אחרונה.

* **סיום:** קיים **סט מוגדר לעריכה**.
* 📋 שני התת-שלבים מוצגים כשלב אחד עם שני מצבים, לא כשני שלבים בפס.

### שלב 4 — עריכה
* בונים מתכון על תמונת ייחוס → מחילים על הסט → **רינדור כמשימת רקע**.
* מצב **"בדיקה"** על התמונה הפתוחה: רזולוציה מלאה, תצוגת הפרש, דוח "מה הכלי עשה", סימון ובחירה (📋 §5.6 במסמך המוצר).
* **סיום:** 🔒 **כל תמונות הסט עברו רינדור בפועל** — לא "הוקצה להן מתכון". זו הבעיה מספר 1 בביקורת, ותנאי הסיום הזה הוא מה שסוגר אותה.
* **תמיד גלוי:** נערכו X מתוך Y · ממתינות לרינדור Z.

### שלב 5 — אלבום (אם הוגדר)
בחירת תמונות → טיוטה אוטומטית → עריכת כפולות → **הגהה ללקוח** → הערות → גרסה חדשה → אישור → ייצוא לדפוס.
* **סיום:** גרסה מאושרת + חבילת דפוס יוצאה.

### שלב 6 — מסירה
* **שלוש דרכים 🔒:** תיקייה מיוצאת · גלריה לצפייה ובחירה · קישור לאישור אלבום.
* **לפני כל שליחה — מסך "מה יוצא":** כמה תמונות, באיזה גודל, ומה **נשאר** על המחשב. פעם אחת, בבירור.
* **מצבים מוצגים:** נשלח · נצפה · נבחר · אושר.
* **גלריה שנשלחה היא צילום רגע.** עריכה מאוחרת ⇦ "עדכן ללקוח", עם ציון שהגרסה אצל הלקוח ישנה.

## 6. שלוש זרימות מלאות

### 6.1 פרויקט חדש → עריכה → מסירה

| # | הצלם עושה | המערכת עושה | מה גלוי |

## 7. משטח הלקוח — שלד נייד

**מי המשתמש:** אדם שנכנס פעם או פעמיים בחיים, בנייד, בערב, אולי מראה לבן זוג. ⛔ בלי הרשמה, בלי הדרכה, בלי צפיפות.

### 7.1 מסכים

**1. פתיחה** — שם הצלם/הסטודיו · "הגלריה של משפחת כהן" · שדה קוד · כפתור אחד. משפט אחד שמסביר מה מצופה ממני.

**2. גלריה** — רשת תמונות גדולות, גלילה אינסופית · הקשה = מסך מלא · לב = בחירה · **מונה קבוע ונגיש לאגודל**: "בחרת 34" · מסננת: הכול / נבחרו.

**3. תמונה מלאה** — החלקה בין תמונות · לב גדול · יציאה ברורה. בלי זום מסובך, בלי כלים.

**4. סיום בחירה** — סיכום ("בחרת 34 מתוך 380") · הערה חופשית · אישור. אם יש מכסה בחבילה — מוצגת כאן בבירור.

**5. אלבום להגהה** — כפולות בגלילה אנכית · הקשה על כפולה = הגדלה + הוספת הערה · שני כפתורים: **מאשר** / **מבקש תיקונים**.

**6. תודה** — מה קורה עכשיו ומתי לצפות לתשובה. הלקוח לא נשאר תלוי באוויר.

### 7.2 מצבים שחייבים תצוגה

קישור פג · הגלריה עודכנה מאז הביקור האחרונה · הבחירה ננעלה · אין חיבור · טעינה איטית (תצוגה מדורגת, לא מסך לבן).

### 7.3 אילוצים
אגודל אחד · טקסט גדול · הכי הרבה שתי פעולות במסך · עובד על חיבור סלולרי חלש · **התמונות הן גרסאות תצוגה בלבד** 🔒.

❓ **פתוח:** סימן מים · תוקף הקישור · האם מותר לשתף הלאה (סבתא) · הורדה של תצוגה.

## 9. מידע שחייב להישאר גלוי לאורך כל העבודה

### 9.1 פס המצב של הפרויקט — שורה אחת, בכל שלב 🔒

1. **מי ומה** — לקוח · פרויקט · סוג אירוע · תאריך.
2. **איפה** — השלב הנוכחי ומצבו.
3. **המונים** — יובאו → נשארו → נבחרו → נערכו → נמסרו. **זהו עמוד השדרה**: השאלה שחוזרת כל היום היא "כמה נשאר".
4. **על מי מחכים** — "ממתין ללקוח מ-12.05" או "אצלי".
5. **משימת רקע פעילה** — מה רץ, כמה אחוז, ואיך עוצרים.
6. **נגישות הקבצים** — זמינים / כונן מנותק.

### 9.2 מה מופיע רק כשיש בעיה
מצב המנוע · אין מקום בדיסק · אין חיבור · מנוי שפג. 📋 מצב תקין אינו ראוי לפיקסלים.

### 9.3 מה נשמר בין מעברים 🔒
התמונה הפתוחה, הזום, המתכון, מיקום הגלילה, סינון שהתחיל. יציאה וכניסה — חוזרים בדיוק לאותה נקודה.
